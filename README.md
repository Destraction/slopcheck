# slopcheck

Детектор «AI slop» без ИИ: оркестратор поверх зрелых open-source статических анализаторов. Находит дубли, мёртвый код, лишние комментарии, недостаток документации и сложность; сводит в единый отчёт со slop-score. В CI валит PR, только если тот **добавил** slop (delta к baseline).

Ядро 100% детерминированное, офлайн, без LLM.

Опциональный `--llm-review` (off по умолчанию) добавляет субъективные замечания
(имена, абстракции, границы модулей), которые статика не берёт. Работает через
**локальный Gemini CLI** (бесплатный OAuth-вход, без API-ключа, не тратит лимит
Claude). Разовая настройка — выполнить `gemini` в терминале и пройти Google-логин.
Замечания идут с severity INFO (гейт по умолчанию не валят).

Подробный план и архитектура — в [PROJECT.md](./PROJECT.md).

## Статус

v1 готов: 4 категории детекторов, отчёты (console/json/sarif/md), delta-гейт, Docker, GitHub Action.

v2 (в работе), уже сделано:
- semgrep-адаптер смеллов (`slopcheck/rules/smells.yml`, категория complexity) — антипаттерны в Python (проглоченные исключения, изменяемые дефолты, `== None`), JS/TS (пустой catch, `debugger`, нестрогое `== null`) и Go (проигнорированная ошибка `_ =`, `panic`);
- LLM-ревью на локальном Gemini CLI (`--llm-review`);
- инкрементальный режим `--changed` (staged / относительно ref);
- находки aislop разносятся по категориям (мёртвый импорт → dead_code, debug-print → complexity), а не сваливаются в comments;
- шумовые срабатывания вычищены дефолтами конфига (см. таблицу ниже);
- **Go** — golangci-lint v2 с пакетным набором: проигнорированные ошибки (errcheck),
  неиспользуемый код (unused, ineffassign), пустые `if err != nil {}`, баги
  staticcheck, экспорт без doc-комментария (revive);
- **React/TS** — ESLint с пакетным конфигом: правила хуков и зависимости
  `useEffect`, `key={index}`, список без `key`, `any`, `@ts-ignore`, пустые catch,
  неиспользуемые переменные, экспорт без JSDoc;
- knip и golangci-lint находят проекты в подкаталогах (Go в корне, фронт в `web/`).
- **комментарии-пересказы** в Go и JS/TS (`restating-comments`): `// Fetch the data`
  над `fetchData()`. Почти все слова комментария должны совпасть с именами строки
  ниже; строковые литералы, doc-комментарии объявлений, поля структур Go и
  метки с двоеточием не считаются. На корпусе калибровки — 10 находок на 6 репозиториев;
- **лишняя защитность и абстракции**: Go-интерфейс с единственной реализацией
  в модуле и без моков в тестах (`go-single-impl`, info; экспортируемые интерфейсы
  библиотечных пакетов не проверяются), `useMemo` вокруг литерала или чтения поля
  (info), `except: raise` без обработки в Python. Лишний `useCallback` не ловится:
  это видно только по тому, куда передаётся функция;
- **TS с типами** (`eslint-typed`) — промис без `await`, async-функция там, где
  ждут обычную, `await` не-промиса, лишние приведения. Нужны установленные
  `node_modules`: без них типы библиотек становятся `any`, и правила врут. Нет
  зависимостей при наличии `tsconfig.json` — детектор помечается пропущенным. В CI
  ставьте зависимости (`npm ci`) до прогона slopcheck, чтобы включить его;

Осталось: HTML-дашборд, автофикс в CI (сейчас — локальный скилл).

## Установка (dev)

```bash
pip install -e ".[dev]"
slopcheck version
```

### Детекторы: без них счёт неполный

Сам slopcheck только собирает и взвешивает находки — ищут их внешние тулы.
Локально (без Docker) их надо поставить, иначе категория останется
непроверенной:

```bash
pip install vulture deptry semgrep   # dead_code, зависимости, смеллы
npm install -g jscpd knip            # duplication, мёртвый код JS/TS
# React/TS:
npm install -g eslint@9 typescript typescript-eslint \
  eslint-plugin-react eslint-plugin-react-hooks eslint-plugin-jsdoc
# Go (нужен и сам Go-тулчейн):
brew install golangci-lint           # v2
```

Go-код должен компилироваться (`go build ./...`): иначе golangci-lint
не запускает линтеры, и slopcheck честно помечает Go-проверки пропущенными.

`lizard` и `interrogate` приезжают вместе с пакетом. `aislop` ставится из npm
(`npm install -g aislop`) — без него не проверяется главная категория, ради
которой всё затевалось, поэтому в Docker-образе он обязателен.

> Непроверенная категория **не получает 100** и **не идёт в итоговый счёт** —
> она помечается «не проверялась», а под таблицей печатается предупреждение,
> что счёт неполный. Раньше ноль находок у незапущенного детектора читался как
> чистый код и завышал итог: на реальном проекте это дало 53.6 вместо 7.6.
> Список пропущенных тулов всегда печатается в конце вывода — если он не
> пуст, счёт охватывает не всё.

## Использование

```bash
slopcheck run ./path/to/repo --format console   # json | sarif | md
slopcheck gate ./repo --baseline base.json      # delta-гейт для CI (exit 1 при регрессе)
slopcheck check-changed ./repo                  # новые относительно HEAD находки незакоммиченных правок
slopcheck check-changed ./repo --staged         # то же по индексу (pre-commit)
```

`check-changed` показывает только то, что внесли правки: старый долг
изменённых файлов не выводится. Если находок уровня `hook_severity` нет,
HEAD не перепроверяется, и команда остаётся быстрой. Иначе те же файлы
прогоняются во временном `git worktree` на HEAD и сравниваются. Коды выхода:
0 — новых находок нет, 1 — есть, 2 — не git-репозиторий или сбой git.

## Выдуманные пакеты (`--check-deps`)

ИИ иногда импортирует пакет, которого не существует. Злоумышленники
регистрируют такие имена (slopsquatting), и установка ставит их код.
`--check-deps` сверяет с реестрами зависимости `package.json`, `go.mod`,
`requirements*.txt` и `pyproject.toml`, а также импорты JS/TS и Go.
Ненайденный пакет — находка уровня error. Импорты Python не сверяются: имя
модуля часто не совпадает с именем пакета (`yaml` ставится как PyYAML).

Ядро slopcheck офлайн, поэтому проверка выключена по умолчанию. В шаблоне CI
флаг включён. Ответы реестров кэшируются в `~/.cache/slopcheck`
(`SLOPCHECK_CACHE_DIR`): найденный пакет — на 7 дней, ненайденный — на день.
Нет сети или реестр ответил ошибкой — проверка помечается пропущенной, а не
выдаёт находки.

## Хуки: ловить slop при написании, а не в CI

**Claude Code (Stop-хук).** В конце каждого хода агента slopcheck проверяет
незакоммиченные правки. Если они добавили slop уровня `hook_severity`, агент
получает список находок и чинит их в том же ходе.

```bash
slopcheck install-hook claude          # в ~/.claude/settings.json (бэкап рядом, .bak-slopcheck)
```

Хук работает только в репозиториях с `.slopcheck.yml`, в остальных молчит.
Повторно в том же ходе не блокирует (`stop_hook_active`), так что агент не
зацикливается. Проверка ограничена 120 с; сбой или таймаут ход не блокируют.

**git pre-commit.** Коммит, добавивший slop в индекс, отклоняется:

```bash
slopcheck install-hook git             # .git/hooks/pre-commit; чужой хук — только с --force
```

или через фреймворк [pre-commit](https://pre-commit.com) (slopcheck и
детекторы должны быть установлены в системе):

```yaml
repos:
  - repo: https://github.com/Destraction/slopcheck
    rev: <тег или sha>
    hooks:
      - id: slopcheck
```

## Docker (все детекторы в одном образе)

Собирать в окружении с открытой сетью (npm-registry, GitHub releases):

```bash
docker build -t slopcheck .
docker run --rm -v "$PWD":/src slopcheck run /src --format console
```

Образ несёт node-детекторы (jscpd, knip, aislop, eslint с плагинами),
Go-тулчейн с golangci-lint и Python-детекторы (vulture, deptry, interrogate,
lizard, semgrep). Зависимости Go-модулей качаются при прогоне, поэтому
контейнеру нужна сеть. Сборка падает, если не встал aislop:
молча пропущенный детектор AI-slop делает зелёный гейт бессмысленным.
Недоступный локально (вне Docker) детектор пропускается с пометкой в отчёте.

## Конфиг `.slopcheck.yml`

`slopcheck init-config` пишет файл со всеми полями и дефолтами. Ключевое:

| Поле | Дефолт | Зачем |
| --- | --- | --- |
| `ignore` | node_modules, .venv, `.claude`, кэши… | пути вне анализа; список **замещается**, а не дополняется |
| `gate_severity` | `warn` | с какого уровня новая находка валит гейт |
| `dup_min_tokens` / `dup_min_lines` | 50 / 5 | порог чувствительности jscpd |
| `dup_ignore_formats` | `[markdown]` | форматы, где повтор — норма (проза, примеры команд) |
| `ignore_rules` | — | правила любых детекторов, выключенные целиком: rule_id или glob (`jsdoc/*`), без учёта регистра |
| `aislop_ignore_rules` | `[python-formatting]` | устаревший алиас `ignore_rules`, читается вместе с ним; форматирование — забота форматтера |
| `hook_severity` | `warn` | с какого уровня новая находка возвращается агенту хуком и `check-changed` |
| `check_deps` | `false` | сверять пакеты с реестрами npm / Go proxy / PyPI (ходит в сеть; то же, что `--check-deps`) |
| `private_packages` | — | свои пакеты, которых нет в публичных реестрах: glob (`@mycorp/*`, `git.corp.io/*`); для Go учитывается и `GOPRIVATE` |
| `dead_code_ignore_decorators` | typer/click/flask/fastapi/pytest | функция, зарегистрированная декоратором, не мёртвая |
| `dead_code_ignore_names` | — | точечные исключения по имени |
| `docstrings_skip_tests` | `true` | докстринги в тестах не требуются: имя теста и есть описание |
| `categories` | все включены, вес 1.0 | включение/вес категории в итоговом счёте |

Имена без подчёркивания vulture считает используемыми только по факту вызова:
намеренно неиспользуемый параметр называйте `_kw`, а не `kw`.

## CI (GitHub Actions)

Готовый composite-action — `action.yml`; полный пример PR-workflow с delta-гейтом
и загрузкой SARIF в Code Scanning — [.github/workflows/example.yml](.github/workflows/example.yml).
