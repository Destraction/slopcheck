# Калибровка slopcheck

Корпус живых OSS-репозиториев (`corpus.yml`), закреплённых на коммите. Бенч
меряет долю шума: сколько находок полезны, а сколько — ложные срабатывания.
Порог из DoD v3 — шум не больше 20% среди размеченных находок уровня warn+.

## Прогон

```bash
uv run python bench/run.py run                    # все репо: клон → slopcheck → таблица
uv run python bench/run.py run --only cobra       # один репо
uv run python bench/run.py run --docker slopcheck:dev   # тем же образом, что в CI
uv run python bench/run.py report                 # только таблица по сохранённому
```

Клоны лежат в `~/.cache/slopcheck-bench`; повторный прогон на том же коммите
сеть не трогает (кроме зависимостей Go-модулей при первом анализе).
Находки — в `bench/out/` (не коммитятся). Для локального прогона нужны все
детекторы из README slopcheck; `--docker` берёт их из образа.

## Разметка

```bash
uv run python bench/run.py label cobra --per-rule 15
```

дописывает в `labels/cobra.yml` до 15 неразмеченных находок на правило с
`verdict: "?"`. Проставьте `useful` или `noise` и одной строкой `why`.
Ключ находки не содержит номера строки, поэтому разметка переживает
пересборку корпуса; `where` — только подсказка, где смотреть.

Подтверждённый шум закрепляется тестом в `tests/noise/`: фикстура с кодом,
на котором находки быть не должно.

## Калибровка (G9, 16.11.2026)

Разметка — `labels/*.yml`: каждая находка из выборки (до 15 на правило в
репозитории) просмотрена в контексте кода, у вердикта есть причина `why`.
Признаки шума перенесены в `src/slopcheck/calibrate.py` (понизить до info
или отбросить) и в конфиги детекторов; каждый закреплён тестом в
`tests/noise/`.

Остаток шума (warn+), признак не выделен без потери настоящих находок:

- `knip-exports` в вендоренном UI-ките (`components/ui` в стиле shadcn):
  12 из 15. Экспорт и правда не используется, но это API набора
  компонентов. В своём проекте — `ignore` на каталог кита;
- `react/no-array-index-key` с составным ключом (`title + index`): 4 из 12;
- `set-state-in-effect` для флага `mounted`: 2 из 3;
- единичные: `console.log` при старте сервера, пояснительные комментарии,
  которые aislop считает нарративом.

`jsdoc/require-jsdoc` (298, info) и `revive/exported` (info) — на счёт и
гейт не влияют. Это стиль документации, а не slop.

## Пополнение корпуса

Добавьте запись в `corpus.yml` (`name`, `url`, `commit`, опционально `path`).
Коммит берите из `git ls-remote <url> HEAD` и не двигайте без причины:
сдвиг коммита меняет находки и обесценивает разметку.

## Корпус ИИ-кода: полнота (v4)

Второй корпус отвечает на обратный вопрос: сколько slop в коде агентов
slopcheck **пропускает**. Две заготовки (`ai/seeds/`: Go-сервис на
`net/http`, Vite + React + TS) и 16 задач (`ai/tasks.yml`), сформулированных
как обычные просьбы пользователя, без упоминания slop. Каждую задачу решали
субагенты Claude Sonnet и Claude Haiku: 32 патча в `ai/out/<модель>/`.

```bash
uv run python bench/ai/generate.py prepare go-auth sonnet   # рабочая копия заготовки
uv run python bench/ai/generate.py collect go-auth sonnet   # патч в ai/out/
uv run python bench/ai/generate.py gemini go-auth           # то же через Gemini CLI
uv run python bench/run.py recall --rerun --unmatched       # прогон и отчёт
```

Разметка — `ai/truth/<модель>/<задача>.yml`: случаи slop, найденные при
чтении патча без оглядки на slopcheck. После прогона находки без пары
перепроверены. Настоящие пропуски разметки дописаны с пометкой
«(при сверке)»: неиспользуемый импорт и экспортированные типы, которые
снаружи не используются. Остальное — шум.

`recall` накладывает патч на заготовку, ставит зависимости (`npm install`,
`go mod download`) и гоняет slopcheck с `--check-deps`. Учитываются только
**новые** находки, которых не было на чистой заготовке. Случай пойман, если
есть находка в том же файле, ±2 строки, правило подходит к типу случая.

(общие инструкции Claude Code), разметку делал Claude.

### После волны 2 (16.11.2026)

Что изменилось:
- H3 — шум warn+ на ИИ-коде: `act()` в тестах, async-обработчики в JSX,
  сброс флагов перед загрузкой в эффекте, ref «последнего значения»,
  русские комментарии в детекторе пересказов;
- H4 — Go: новая ошибка без исходной в `if err != nil` (`go-error-wrap`);
- H5 — комментарии-разделители (`separator-comments`);
- H7 — обходы линтера (`lint-suppressions`). Новое подавление без причины — warn,
  в том числе в `recall`, как в гейте и хуке.

Один случай переклассифицирован: `// --- … ---` из `restating-comment` в
новый тип `separator-comment`. Других изменений разметки нет.

| | до волны 2 | после | цель К1 |
|---|---:|---:|---:|
| поймано любой находкой | 11 из 21 (52%) | 14 из 21 (67%) | ≥ 65% |
| поймано warn+ | 9 (43%) | 12 (57%) | ≥ 55% |
| точность warn+ на ИИ-коде | 9 из 23 (39%) | 12 из 12 (100%) | ≥ 70% |
| шум warn+ на OSS-корпусе | 10% | 9% (32 из 342) | ≤ 20% |

Новые правила на OSS-корпусе:
- `separator-comment` — 5 находок в cobra и тестах gotify, все полезные;
- `error-no-wrap` — 4 находки, 2 из них шум: gotify `plugin.Lookup` → «missing symbol»,
  новое сообщение говорит то же, что исходная ошибка;
- `lint-suppression` — 46 подавлений без причины и 26 с причиной, все info
  (в полном прогоне не штрафуют).

Не ловится по-прежнему:
- over-defensive (5 случаев): недостижимые проверки, двойной таймаут.
  Общего признака нет, детектор не делали (решение К1);
- `cancelLabel` — проп «на вырост» с дефолтом, который никто не передаёт;
- русский пересказ в JSDoc (`/** Повторить загрузку. */`).
